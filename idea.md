# Lost & Found Board

**Stack:** Node.js + Express + JSON file storage on the backend, React on the frontend

---

## 1. The Problem

Things go missing on campus every day. Someone leaves a water bottle in the lab, someone else finds a set of keys near the canteen, and both end up posting on a WhatsApp group where the message is buried within an hour.

Build a small web app where anyone can post an item they **lost** or **found**, browse what others have posted, filter the board, and mark an item as claimed once it finds its way home.

You will build both the API and the React frontend that talks to it.

---

## 2. Data Model

Every item is stored as one object in `items.json`:

```json
{
  "id": "a3f2c1",
  "itemName": "Black leather wallet",
  "type": "lost",
  "place": "Library",
  "date": "2026-09-05",
  "contact": "zeeshan@college.edu",
  "status": "open"
}
```

| Field      | Type   | Rules                                                     |
| ---------- | ------ | --------------------------------------------------------- |
| `id`       | string | Generated by the server. Never sent by the client.        |
| `itemName` | string | Required, non-empty                                       |
| `type`     | string | Required, `"lost"` or `"found"`. Set once, never changes. |
| `place`    | string | Required, non-empty                                       |
| `date`     | string | Required, `YYYY-MM-DD`                                    |
| `contact`  | string | Required, non-empty                                       |
| `status`   | string | `"open"` or `"claimed"`. Server sets `"open"` on create.  |

The file starts as an empty array: `[]`

Note that `type` and `status` are deliberately kept apart. `type` records what kind of report it is; `status` records whether the report is still active. Merging them into one field would lose information the moment an item is claimed.

## 3. Core Endpoints

Build these in order. Get the first two working end-to-end before moving on to the rest.

### 3.1 `POST /api/items` — Report an item

Accepts `itemName`, `type`, `place`, `date`, `contact`.

The server generates `id` and sets `status` to `"open"`. If the client sends either of those, ignore them.

| Case                                | Response                 |
| ----------------------------------- | ------------------------ |
| Valid body                          | `201` + created object   |
| Missing any required field          | `400` + `{ "error": … }` |
| `type` is not `"lost"` or `"found"` | `400` + `{ "error": … }` |

### 3.2 `GET /api/items` — List the board

Returns an array of all items, **newest first**.

Support these optional query params. They must work individually and in combination:

| Param    | Example        | Behaviour                      |
| -------- | -------------- | ------------------------------ |
| `type`   | `?type=lost`   | Exact match                    |
| `status` | `?status=open` | Exact match                    |
| `place`  | `?place=lib`   | Case-insensitive partial match |

`GET /api/items?type=found&status=open&place=canteen` returns unclaimed found items from the canteen.

> **Hint:** Start with the full array and apply one `.filter()` per param that was actually provided.

### 3.3 `GET /api/items/:id` — Single item

| Case       | Response                           |
| ---------- | ---------------------------------- |
| Found      | `200` + the object                 |
| No such id | `404` + `{ "error": "Not found" }` |

The 404 body must be JSON, not Express's default HTML error page.

### 3.4 `PUT /api/items/:id` — Edit a report

Replaces `itemName`, `type`, `place`, `date`, `contact`. Same validation as `POST`.

`id` and `status` are not editable here. Strip them from the incoming body explicitly — do not spread the request body over the stored object and hope for the best. A client could otherwise mark anything as claimed through this route.

| Case           | Response               |
| -------------- | ---------------------- |
| Valid + exists | `200` + updated object |
| Invalid body   | `400`                  |
| No such id     | `404`                  |

### 3.5 `PATCH /api/items/:id/claim` — Mark as claimed

Sets `status` to `"claimed"`. Nothing else changes.

This gets its own route rather than going through `PUT` because it is a distinct real-world action and maps to a single button in the UI.

| Case            | Response                 |
| --------------- | ------------------------ |
| Was open        | `200` + updated object   |
| Already claimed | `409` + `{ "error": … }` |
| No such id      | `404`                    |

### 3.6 `DELETE /api/items/:id` — Remove a report

| Case       | Response          |
| ---------- | ----------------- |
| Deleted    | `204`, empty body |
| No such id | `404`             |

Since claiming already handles the normal end of an item's life, delete exists for spam and mistakes only.

## 4. Frontend

React. Vite is the fastest way to start:

```
npm create vite@latest client -- --template react
```

Run the API and the React dev server on different ports and point your requests at the API's full URL. You will hit CORS on your first request — that is expected, and fixing it with the `cors` package is part of the exercise.

`fetch` is enough. No state management library, no component library.

### 4.1 Board

```
┌──────────────────────────────────────────────────────────┐
│  LOST & FOUND                          [ + Report Item ] │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  [ All ]  [ Lost ]  [ Found ]      Place: [_________]    │
│  [ ] Hide claimed                                        │
│                                                          │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ [LOST]  Black leather wallet                       │  │
│  │ Library · 05 Sep 2026                              │  │
│  │ zeeshan@college.edu                                │  │
│  │              [ Claim ]  [ Edit ]  [ Delete ]       │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ [FOUND] Set of keys, blue keychain      ✓ CLAIMED  │  │
│  │ Canteen · 04 Sep 2026                              │  │
│  │ 98765xxxxx                                         │  │
│  │                         [ Edit ]  [ Delete ]       │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

Requirements:

- Items load on mount via `GET /api/items`
- The `[LOST]` / `[FOUND]` badge is visually distinct — two colours is enough
- A claimed card is visibly dimmed and shows the `✓ CLAIMED` marker
- The Claim button disappears once an item is claimed
- Type buttons, the place box, and the Hide claimed checkbox re-call the API with query params. **Filter on the server, not by filtering an array already in React state**
- Empty result renders a message, not a blank column

### 4.2 Report / Edit Form

One component serves both. Empty for create, pre-filled for edit.

```
┌────────────────────────────────────────────┐
│  Report an Item                       [ × ]│
├────────────────────────────────────────────┤
│                                            │
│  Item name                                 │
│  [________________________________]        │
│                                            │
│  Type                                      │
│  ( ) I lost this    ( ) I found this       │
│                                            │
│  Place                                     │
│  [________________________________]        │
│                                            │
│  Date                                      │
│  [ dd / mm / yyyy ]                        │
│                                            │
│  Contact (email or phone)                  │
│  [________________________________]        │
│                                            │
│  ⚠ Item name is required                   │
│                                            │
│              [ Cancel ]   [ Submit ]       │
└────────────────────────────────────────────┘
```

Requirements:

- Controlled inputs, one piece of state for the whole form object
- Submit calls `POST` when creating and `PUT /api/items/:id` when editing
- When the API returns `400`, render the server's error message in the warning row. Your API is the source of truth, not the browser's built-in validation
- On success, close the form and refresh the list

## 5. Aspirational Topics

Finish the core work first. Each of these is independent, so pick whichever you find interesting.

**Pagination.** Change the list response to `{ data, total, page, totalPages }` and add Prev/Next. Note how one server-side change ripples through every component that touched the old response shape.

**Photo upload.** Add `multer` on the server, keep the filename on the item, delete the file when the item is deleted.

**Deploy it.** Render or Railway. Then work out why your data disappears on redeploy.
